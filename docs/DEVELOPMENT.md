## Инструменты и локальный запуск

Нужны Roblox Studio, Foreman и Python 3.9+. В [foreman.toml](../foreman.toml)
закреплены Rojo 7.7.0 и Lune 0.10.5, чтобы локальная сборка совпадала с CI.

```sh
foreman install
python3 tools/check.py
rojo build --output /tmp/infinite-chocolatier.rbxlx
```

`tools/check.py` проверяет CSV локализации, запускает Luau- и Python-тесты,
собирает place и проверяет пробелы в diff. Он сохраняет отдельные логи,
отпечаток исходников и `report.json` в новой временной папке.
Подробности и выбор папки — в [tools/CHECK.md](../tools/CHECK.md).

Откройте сборку через File → Open в **одном** окне Roblox Studio, затем Play.
Локальная сцена использует сессию в памяти, без настоящих DataStore-профилей.
Проверки нескольких игроков с дополнительными окнами требуют согласования.
Правила запуска и восстановления — в [STUDIO_RUNBOOK.md](../STUDIO_RUNBOOK.md).

## Устройство исходников

```text
src/
├── client/       интерфейс, ввод, сцена, прогулка и звук
├── server/       ручные раунды, экономика, профили и рейтинги
└── shared/       геометрия, рецептура, баланс и общие правила
tests/            тесты Luau и Python
localization/     CSV для Roblox и описание локализации
tools/            проверки, сборка локализации и сценарии QA
docs/             руководства и изображения для GitHub
```

[default.project.json](../default.project.json) сопоставляет три папки `src`
с ReplicatedStorage, ServerScriptService и StarterPlayerScripts.
Документация, маркетинговые файлы и исторический архив в place не попадают.

| Модуль | Ответственность |
| :--- | :--- |
| [Config.luau](../src/shared/Config.luau) | Рисунок плитки, баланс и настройки игры |
| [Geom.luau](../src/shared/Geom.luau) · [Recipe.luau](../src/shared/Recipe.luau) | Чистая геометрия и этапы фокуса, без Roblox-сервисов и UI |
| [Economy.luau](../src/shared/Economy.luau) | Правила дохода, покупок и развития ателье |
| [Клиент](../src/client/) | Ввод, отображение этапов, окна, звук и прогулка |
| [Сервер](../src/server/) | Проверка последовательности раунда, наблюдателей и назначение награды |

Клиент сообщает о начале, этапах и завершении ручного раунда. Сервер
проверяет порядок и назначает число долек: интерфейс не определяет доход
и не отправляет произвольные очки в общий рейтинг.

## Проверки и границы приёмки

Перед коммитом обязательны:

```sh
lune run tests/run
rojo build --output /tmp/infinite-chocolatier-check.rbxlx
```

Полная локальная проверка через `python3 tools/check.py` включает обе команды.
Тесты покрывают геометрию, ввод, экономику, сохранения и серверные обработчики
с подменёнными сервисами. Проверки Studio и сценарии QA описаны
в [tools/STUDIO_QA.md](../tools/STUDIO_QA.md).

Успешная сборка не подтверждает настоящий телефон, облачные сохранения после
повторного входа, взаимодействие двух живых игроков или содержимое облачного
рейтинга. Эти результаты фиксируются отдельно.

## Локализация и звук

Тексты поддерживаются на русском и английском. После изменения строк:

## Сцена и ручной фокус

3D-вид: шоколадка лежит на деревянной доске, нож следует
жесту, при нарезке разлетаются крошки, а соединение сопровождают искры.
Нож имеет цельный профиль сантоку с фаской и скруглённой рукоятью.
Общая для игрока и стажёров опора на кончик удерживает лезвие над дольками;
цель для руки стажёра вычисляется из нового положения рукояти.
Рукоять направлена по движению жеста: игрок и стажёр тянут нож.
Второй и четвёртый разрезы выполняются снизу вверх; диагональ и горизонтальный
разрез сохраняют направление слева направо. Подсказки и стажёры следуют тем же путям.
Лезвие держится вертикально к доске, без бокового завала; до начала жеста
сохраняется тот же хват. Небольшой подъём рукояти не отклоняет кромку от линии.
Автоматические разрезы занимают время пропорционально длине в 3D: скорость
ножа одинакова на диагонали и коротких резах. Нарезка по-прежнему занимает
45% цикла; скорость производства и доход от этого изменения не меняются.
После ручного фокуса нож и подсказка следующего разреза появляются уже при
исчезновении наградной дольки. Награда анимируется отдельной копией и не
блокирует ввод; завершение эффекта не сбрасывает начатый разрез.
Вертикальный экран сохраняет компактный интерфейс, широкий — боковое ателье.
Прежний рендер сохранён: `Config.Scene3D.enabled = false` возвращает 2D;
точка отката до эксперимента — `812f984` (версия 17).

## Сохранения и диагностика

Опубликованная игра использует `ChocolateAtelier_v1`, автосохранение каждые
30 секунд, сохранение при выходе и закрытии сервера. Профиль защищён арендой
записи; ошибка загрузки не заменяет существующий профиль пустым.
После аварийного закрытия могут потеряться изменения после последнего
успешного сохранения. Схема профиля и миграции описаны в HANDOFF.

Владелец видит кнопку версии внизу слева. Она открывает копируемый отчёт:
версия, режим, этап фокуса, сохранение, баланс, улучшения и загрузка друзей.
`Studio` означает локальную сессию, `vN` — опубликованную версию.
Отчёт доступен только `BalanceTesterUserId`; снимок обновляется при открытии.

## Публикация

Workflow [roblox-deploy.yml](../.github/workflows/roblox-deploy.yml) запускается
при push в `main` и вручную. Он проверяет локализацию, выполняет тесты,
собирает place и отправляет его в Roblox через Open Cloud.
Ключ `ROBLOX_API_KEY` хранится в GitHub Secrets, а не в исходниках.

Обновление только документации можно отправить с `[skip ci]` в сообщении
коммита, чтобы оно не выпускало новую игровую сборку.
Это поведение описано в [документации GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs).
Для игрового выпуска нужны согласованный состав изменений, успешная проверка
и числовой `versionNumber` Roblox; сам факт push не подтверждает публикацию.
