# Локальная проверка Studio без управления окнами

`studio_qa.py` использует встроенный Studio MCP через stdio. Зависимости:
Python 3.9+, локальная Roblox Studio с включённым MCP и уже открытая тестовая
копия проекта. Пакеты pip и облачные ключи не требуются.
Процессу нужен доступ к локальной сети: Studio подключается к proxy через
localhost. Запуск внутри песочницы с запрещённой сетью может вернуть пустой
список сцен, хотя окно Studio открыто. Инструмент ждёт регистрацию до 30 с,
но сам не меняет разрешения сети и не перезапускает редактор.

## Подготовка

Собрать текущий проект:

```sh
rojo build -o /tmp/infinite-chocolatier-qa.rbxlx
```

Один раз открыть эту копию в Studio, включить её MCP и оставить Edit.
Инструмент сам не открывает окна, не переключает рабочие столы и не запускает
Roblox Player. Для существующей копии `chocolatier-diagnostics.rbxlx` имя можно
не указывать; для новой использовать `--place-name infinite-chocolatier-qa.rbxlx`.
Рабочую опубликованную сцену инструмент отвергает по PlaceId и имени.

## Команды

```sh
python3 tools/studio_qa.py list
python3 tools/studio_qa.py check
python3 tools/studio_qa.py sync
python3 tools/studio_qa.py smoke
python3 tools/studio_qa.py gestures
```

`list` читает список подключённых редакторов. `check` проверяет, что выбранная
копия локальная, не запущена и содержит дерево нашего проекта. `sync` обновляет
44 исходника (число вычисляется по src), добавляет новые модули и проверяет
прочитанный обратно Source. Неизвестный оставшийся скрипт считается ошибкой:
пересобрать копию через Rojo, а не молча удалять чужое содержимое.

`smoke` временно добавляет тестовый профиль и обработчик в памяти Studio,
запускает Play и проверяет:

- загрузку профиля с 12 кафе и 25 стажёрами;
- реальную серверную покупку craft ×10 и изменение дохода;
- четыре завершённых раунда и переход к следующему заказу;
- открытие/закрытие дневника и наличие офлайн-отчёта;
- русский и английский текст в панели 336 px, отсутствие наложения кнопок;
- домашнего стажёра и шесть подробных станций в очереди кафе;
- видимость новых деталей, перемещения и исключение дальней очереди из обхода;
- покупку и снятие часов, счётчик коллекции, сохранение бонуса и текст всех
  семи разделов каталога на русском и английском;
- отсутствие MessageError в журналах клиента и сервера.

Дополнительно проверяется доставка позы видимого соседа: настоящий KitchenRelay
получает условного автора на расстоянии 256 studs, строит подписку по CafeQueue
и отправляет позу настоящим RemoteEvent в клиент. Дальние неанимированные
комнаты исключаются отдельными Lune-тестами. Это проверка сетевого канала с
тестовым автором, не многопользовательский сеанс с двумя реальными людьми.

`gestures` — отдельный сценарий нативной мыши: четыре разреза, перемещение
большого куска, перемещение полоски и подтверждение ровно одного нового раунда
сервером. Координаты берутся из проекции игры. Обработчик только читает этапы
и геометрию; завершение разреза и отправка награды остаются за обычным Game.
Перед вводом проверяются RenderStepped, размер viewport, границы координат и
отсутствие перекрывающего интерфейса. Жест, после которого этап не изменился,
не повторяется автоматически.

Статус проверки 20 сентября: при заблокированном macOS камера возвращает
1×1, RenderStepped не приходит. Прямая проба user_mouse_input не завершилась
за два ожидания по 30 с; диагностическая сессия затем опознана и очищена
отдельно. Новый сценарий на том же Mac корректно отказывает **до** отправки
мыши и восстанавливает Edit. Положительный полный проход в работающем viewport
пока не подтверждён; переходы сценария покрыты изолированными Python-тестами.
Не объявлять этот режим успешно проверенным нативным вводом до живого прогона.
Обычный `smoke` доступен и без рендера.

После успеха, ошибки или обычного прерывания сценарий останавливает только
собственный Play, возвращает исходники из src и подтверждает Edit. Уже
запущенную сессию пользователя он не прерывает. Параллельный запуск второго
сценария запрещён блокировкой, которая освобождается ОС при выходе процесса.

При таймауте MCP повторная запись не отправляется: очистка сначала ждёт тот
же запрос. Если соединение не позволяет подтвердить восстановление, результат
остаётся неуспешным, а `cleanupError` сообщает об этом. При SIGKILL или падении
Studio автоматическая очистка не гарантируется: после возвращения в Edit
выполнить `sync`. В рабочем src тестовый обработчик никогда не появляется.

## Отчёт и границы проверки

Результат сохраняется в `/tmp/chocolatier-studio-report.json`, другой путь
задаётся через `--report`. Там находятся хеши исходников, этапы, результаты,
журнал Studio, подтверждение очистки и ограничения. Ошибка даёт ненулевой код
завершения. Сценарий не публикует игру и не обращается к настоящим сохранениям:
используется существующая ветка сервера `RunService:IsStudio()`.

Заблокированный macOS может не выполнять RenderStepped. Для проверки кухни
сценарий вызывает её настоящий обработчик кадров явно. Это не доказывает
правильность нативных жестов, плавность картинки или работу на реальном
телефоне. Проверка TextFits и координат не заменяет визуальную приёмку.
Снимки в этот сценарий не входят: известный розовый кадр native MCP и отказ
ScreenCaptureKit при блокировке не скрываются успешным статусом тестов.

Перед выпуском по-прежнему выполнять локально:

```sh
python3 -m unittest discover -s tests -p 'test_studio_qa.py'
lune run tests/run
rojo build -o /tmp/infinite-chocolatier-release.rbxlx
git --git-dir=.git-codex --work-tree=. diff --check
```

В GitHub Actions запускаются только обычные тесты Python/Lune и сборка.
Облачная Roblox Studio или облачные проверки движка не подключены.
