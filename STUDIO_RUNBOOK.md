# Безопасный запуск Roblox Studio

Этот документ нужен, чтобы на слабом MacBook не поднимать несколько Roblox
Studio одновременно.

## Главное правило

`sky.get_app_state` — не только чтение. Если приложение не запущено, этот вызов
может запустить его. Поэтому после закрытия Studio нельзя вызывать
`get_app_state` для проверки: проверка сама способна создать новый экземпляр.

## Канонический экземпляр

Используем только:

```text
/Applications/RobloxStudio.app
```

Не используем для запуска или проверки:

- `/Users/tolya/Library/Roblox/UnzippedBundle/RobloxStudio.app`;
- неоднозначный bundle id `com.Roblox.RobloxStudio`, если среда сообщает, что
  найдено несколько приложений;
- открытие `.rbxlx` через Finder или отдельный вызов приложения.

## Порядок работы

1. Сначала вызвать `sky.list_apps()` и посчитать все записи с
   `displayName == "Roblox Studio"` и `isRunning == true`.
2. Если найден хотя бы один экземпляр, новый не запускать. Работать с уже
   открытым каноническим окном через его меню File/Open.
3. Если экземпляров несколько, переключаться и закрывать их обычным Quit;
   при запросе place выбирать «Не сохранять» только для локальных сборок,
   которые были сгенерированы Rojo и не редактировались вручную.
4. Только если список показывает ноль работающих экземпляров, один раз
   вызвать `get_app_state` с каноническим путём. Это единственный разрешённый
   запуск в рамках сессии.
5. После Quit проверять результат только через `sky.list_apps()`. Нельзя
   вызывать `get_app_state` по закрытому пути: он может поднять Studio снова.

## Что не делать

- Не открывать каждый новый `.rbxlx` через `get_app_state`.
- Не проверять закрытие вызовом `get_app_state` по альтернативному пути.
- Не использовать `killall`/принудительное завершение, пока не обработаны
  обычные запросы сохранения.
- Не запускать параллельно Studio и Rojo-плейс через разные процессы без
  явной необходимости.

## Auto-Recovery

`Ignore` не устраняет предупреждение: recovery-файл остаётся в `AutoSaves`,
поэтому Studio показывает тот же диалог при каждом следующем запуске.

Если появился Auto-Recovery:

1. Не удалять файл вслепую и не продолжать бесконечно через `Ignore`.
2. Сверить дату recovery с канонической DEV-сборкой и историей Git.
3. Если recovery старый или его ценность ещё не ясна, сначала побайтно
   перенести его в `local-recovery-backups/` и проверить SHA-256 копии.
4. Только после сохранения резервной копии убрать исходник из `AutoSaves`.
5. При следующем закрытии сначала остановить Play, обработать запрос
   сохранения place, выполнить обычный Quit и ждать `isRunning == false`
   исключительно через `sky.list_apps()`.

Наличие recovery само по себе не доказывает новое падение Studio. Дату файла
нужно сопоставлять с журналом: строки `About to normally exit`, `AboutToQuit`
и `About to exit the application, doing cleanup` подтверждают штатный выход.
